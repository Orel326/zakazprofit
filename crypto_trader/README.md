# Crypto Trader — сбор данных, аналитическая команда и виртуальный брокер

Изолированный Python-проект внутри репозитория ЗаказПрофит. Он не меняет веб-калькулятор и не отправляет реальные торговые заявки.

## Что реализовано

### Рыночные данные
- Получение закрытых OHLCV-свечей через публичный API OKX Spot по умолчанию (ccxt).
- Binance Spot также поддерживается, если API доступен в регионе.
- Поддерживаемые инструменты: BTC/USDT и ETH/USDT.
- Проверка чисел, OHLC-границ, порядка времени, дубликатов и пропусков.
- Идемпотентное сохранение в SQLite.

### Аналитическая команда — этап 2
- Сканер рынка и технический аналитик.
- Анализ режима рынка и волатильности.
- Новостной аналитик явно сообщает, что новостной источник пока не подключён, и не выдумывает события.
- Контраргументатор формирует три проверяемых возражения для торгового кандидата.
- Риск-менеджер выполняет отдельную проверку с безусловным вето.
- Главный трейдер формирует единственное итоговое решение, но не может отменить вето.
- Все роли обмениваются структурированными отчётами, пригодными для сохранения и последующего аудита.

Текущие роли реализованы как детерминированный, воспроизводимый базовый контур. Это ещё не подключённые языковые модели: интеграцию LLM, проверенные новостные источники и автономный цикл запуска добавим отдельными этапами.

### Виртуальный брокер
- Виртуальный счёт с начальным балансом по умолчанию 10 000 USDT.
- Открытие и закрытие только виртуальных LONG-позиций на споте.
- Учет комиссии и проскальзывания при исполнении.
- Стоп-лосс и тейк-профит; если в одной свече задеты оба уровня, консервативно считается, что первым сработал стоп.
- Ограничение количества позиций, риска на сделку и суммарного открытого риска.
- Журнал входов, выходов, причин закрытия и чистого PnL.
- Снимки капитала с оценкой открытых позиций по переданным рыночным ценам.
- Повторное открытие приложения не сбрасывает виртуальный счёт.

**Важно:** система пока не совершает автономные сделки даже на виртуальном счёте. Команда анализа выдаёт решения WATCH или NO_TRADE; автоматическое исполнение, мониторинг позиций и отчётность по результатам — следующие этапы. Реальные ордера, ключи API, маржа и плечо не используются.

## Установка

Требуется Python 3.11+.

```powershell
cd crypto_trader
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

## Сбор данных

По умолчанию используется OKX. Биржу можно изменить в `.env` через `EXCHANGE_ID`.

```powershell
python -m crypto_trader.cli --days 30 --timeframe 1h
```

## Запуск аналитической команды

После успешной загрузки данных:

```powershell
python -m crypto_trader.team_cli --timeframe 1h --candles 200
```

Команда печатает структурированный JSON-отчёт по каждому инструменту. Она использует только сохранённые закрытые свечи и не открывает позиции.

## Тесты

```powershell
pytest
```

## Структура

- src/crypto_trader/config.py — настройки.
- src/crypto_trader/exchange.py — публичные клиенты OKX/Binance и загрузка свечей.
- src/crypto_trader/quality.py — проверки качества данных.
- src/crypto_trader/storage.py — хранение рыночных свечей.
- src/crypto_trader/analysis.py — EMA, RSI, ATR и классификация рынка.
- src/crypto_trader/team.py — роли агентов, структурированные отчёты и итоговое решение.
- src/crypto_trader/team_cli.py — запуск аналитической команды.
- src/crypto_trader/paper.py — виртуальный счёт, исполнение и журнал сделок.
- tests/ — автоматические тесты.
