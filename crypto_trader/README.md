# Crypto Trader — аналитическая команда и виртуальный брокер

Изолированный Python-проект внутри репозитория «ЗаказПрофит». Веб-калькулятор не затрагивается. Проект использует только публичные рыночные данные и не отправляет реальные торговые заявки.

## Текущий статус

Реализован базовый автономный контур paper trading для BTC/USDT и ETH/USDT на споте:
- получение закрытых OHLCV-свечей через публичный API OKX по умолчанию (CCXT); Binance также поддерживается;
- проверка качества и идемпотентное сохранение свечей в SQLite;
- детерминированные аналитические роли и структурированные отчёты;
- виртуальный брокер с постоянным счётом, комиссиями, проскальзыванием, стоп-лоссом и тейк-профитом;
- непрерывный цикл: данные → анализ → контраргументы → риск-фильтр → решение главного трейдера → виртуальное исполнение;
- сохранение полного JSON-отчёта агентов и решения по каждой обработанной свече в SQLite для последующего аудита;
- защита от повторного входа и ретроактивного стопа при повторной обработке свечи после аварийного перезапуска;
- последовательная обработка пропущенных закрытых свечей после простоя, отдельные контрольные точки для каждой биржи/таймфрейма и остановка при обнаружении пропусков в истории;
- тесты в GitHub Actions для изменений внутри `crypto_trader/`.

**Важно:** роли команды сейчас являются детерминированными программными агентами, а не отдельными LLM. Новостной источник не подключён: новостной риск помечается как неизвестный. Поэтому это рабочий технический прототип автономного симулятора, а не доказанная прибыльная стратегия и не готовый инвестиционный продукт.

## Аналитическая команда

- Сканер рынка и технический аналитик оценивают закрытые свечи.
- Аналитик режима рынка оценивает тренд и волатильность.
- Новостной аналитик не делает выводов без проверенного источника.
- Контраргументатор формирует три возражения для каждого торгового кандидата.
- Риск-менеджер выполняет отдельную проверку с безусловным вето.
- Главный трейдер формирует единственное итоговое решение и не может отменить вето.

Все отчёты структурированы и пригодны для последующего аудита. Сейчас это воспроизводимые правила, не LLM-диалоги.

## Виртуальный брокер и ограничения

- Начальный баланс по умолчанию — 100 USDT.
- Только LONG на споте; без плеча, маржи и реальных заявок.
- Учитываются комиссия и фиксированное проскальзывание.
- Размер позиции рассчитывается по ожидаемому чистому убытку на стопе с учётом комиссий и проскальзывания входа/выхода; суммарный открытый риск считается на той же основе. Гэп через стоп может привести к убытку выше расчётного.
- Сигнал формируется после закрытия свечи и виртуальный вход фиксируется по её цене закрытия с проскальзыванием; диапазон свечи входа не используется для ретроактивного выхода. Стоп и цель проверяются на следующих закрытых свечах. Если внутри одной свечи задеты оба уровня, применяется консервативное предположение: первым сработал стоп.
- Если свеча открылась ниже стопа, исполнение моделируется от цены открытия, а не по недоступной цене стопа. Благоприятный гэп через тейк консервативно исполняется по цене цели.
- Счёт, позиции, журнал сделок, отчёты агентов и контрольные точки цикла хранятся в SQLite и переживают перезапуск.
- После простоя цикл догружает свечи от сохранённой контрольной точки и обрабатывает их по порядку. Если биржа не отдаёт полную историю или в данных обнаружен разрыв, цикл не продвигает контрольную точку: потенциально пропущенный стоп/тейк нельзя безопасно восстановить. При первом старте без позиции история используется для индикаторов, но не проигрывается задним числом как реальные сигналы.

Модель исполнения остаётся упрощённой: нет тикового порядка внутри свечи, реальной глубины стакана, динамического спреда и моделирования сетевой задержки. Результаты симуляции нельзя считать прогнозом реальной доходности.

## Установка (Windows PowerShell)

Требуется Python 3.11+.

```powershell
cd crypto_trader
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

По умолчанию используется OKX. Параметры можно изменить в `.env`:
- `EXCHANGE_ID=okx`
- `DATABASE_PATH=data/market_data.sqlite3`
- `DEFAULT_TIMEFRAME=1h`
- `SYMBOLS=BTC/USDT,ETH/USDT`

API-ключи не нужны.

## Сбор рыночных данных

```powershell
python -m crypto_trader.cli --days 30 --timeframe 1h
```

## Запуск аналитической команды

После загрузки данных:

```powershell
python -m crypto_trader.team_cli --timeframe 1h --candles 200
```

Команда печатает JSON-отчёт и не открывает позиции.

## Автономная виртуальная торговля

Один проход:

```powershell
python -m crypto_trader.paper_cli --once --timeframe 1h
```

Непрерывный режим (остановка Ctrl+C):

```powershell
python -m crypto_trader.paper_cli --timeframe 1h --interval-seconds 60
```

Цикл опрашивает биржу раз в 60 секунд, но торговые решения принимает по закрытым свечам. По умолчанию виртуальный депозит — 100 USDT. Счёт и журнал хранятся в SQLite рядом с рыночными данными. Для нового независимого эксперимента укажи новый `DATABASE_PATH`; не удаляй рабочую базу, если хочешь сохранить историю.

Также доступна команда после установки:

```powershell
paper-trader --once
paper-trader --timeframe 1h --interval-seconds 60
```

## Тесты

```powershell
python -m pytest
```

GitHub Actions автоматически запускает тесты при изменениях в `crypto_trader/`.

## Структура

- `src/crypto_trader/config.py` — настройки.
- `src/crypto_trader/exchange.py` — публичные клиенты OKX/Binance и загрузка свечей.
- `src/crypto_trader/quality.py` — проверки качества данных.
- `src/crypto_trader/storage.py` — хранение рыночных свечей.
- `src/crypto_trader/analysis.py` — EMA, RSI, ATR и классификация рынка.
- `src/crypto_trader/team.py` — аналитические роли и итоговое решение.
- `src/crypto_trader/team_cli.py` — запуск аналитической команды.
- `src/crypto_trader/cycle.py` — автономный цикл и контрольная точка.
- `src/crypto_trader/paper_cli.py` — одноразовый и непрерывный запуск.
- `src/crypto_trader/paper.py` — виртуальный счёт, исполнение и журнал сделок.
- `tests/` — автоматические тесты.

## Что ещё необходимо до серьёзной оценки стратегии

1. Подключить LLM-адаптеры и проверяемые новостные источники, сохранив детерминированный риск-контур.
2. Добавить реалистичную модель спреда, ликвидности, задержек и гэпов на более детальных данных.
3. Сделать полноценный walk-forward backtest без lookahead и с учётом всех издержек.
4. Собирать длительную paper-статистику: число сделок, net PnL, max drawdown, profit factor, expectancy и сравнение с buy-and-hold/простым baseline.
5. Проверить устойчивость вне обучающего периода и восстановление после сетевых/процессных сбоев.

До прохождения этих проверок нельзя делать вывод о прибыльности.
